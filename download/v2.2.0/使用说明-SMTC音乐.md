# 「初始」SMTC 音乐 · v2.2.0 使用说明

> 本轮解决三件事：**① 面板能拖但网易云本体不动（改用网易云客户端内部 API 控制）**
> **② 暂停→再播放的累积漂移（歌词/进度越错越多）** **③ SMTC 桥不再多开一个窗口**。

---

## 一、升级四件套（缺一不可，版本要对齐）

| 组件 | 新版本 | 在哪里 | 怎么装 |
|---|---|---|---|
| 网页版「初始」 | v2.2.0 | 合并包 / GitHub | 打开新标签页按 **Ctrl+F5** 强刷 |
| 扩展版「初始」 | v2.2.0 | `ChuShi-NewTab-v2.2.0.zip` | edge://extensions → 删除旧版 → 开发人员模式 → 加载解压缩扩展 |

## 二、桥的三种用法（v1.6.0 起不再「多开一个窗口」）

1. **推荐·静默常驻**：双击 `添加开机自启.bat`（只需一次）。之后每次开机由
   `bridge-hidden.vbs` 静默拉起，**全程零窗口**。
2. **升级自愈**：换了新电脑路径/新版本文件夹时，把新版解压后双击一次
   `启动SMTC桥.bat`——自启项会自动改指当前文件夹（v1.6.0 自愈），
   若旧实例还占着端口也会被自动接管，不需要你去关旧窗口。
3. **手动诊断**：双击 `启动SMTC桥.bat` 出现的可见窗口仅供看日志，关窗即停。

> 说明：Windows 不允许浏览器页面直接读系统媒体会话，必须有一个本机小进程
> （PowerShell 脚本，零依赖、只监听 127.0.0.1）。v1.6.0 已把它做成「隐身」：
> 不弹窗、开机自启、随新包自愈——体验上等同于并入扩展。

## 三、本轮修复了什么

1. **拖动进度条，网易云本体真的跳了（API 控制）**
   v1.2.0 插件改走网易云客户端内部 API：`playing/setPlayingPosition` dispatch
   → 420ms 后实测校验 → 未生效再退一层直接写播放元素 → 再校验；
   结果（seekAck）回传宿主。SMTC 的 TryChangePlaybackPositionAsync 仍然照发
   （对支持的播放器如 Spotify 依旧有效）。
2. **拖动诚实化**：若播放器两级都没响应，面板进度条 **2.5s 内弹回真实位置**，
   页脚提示「拖动未生效：播放器未响应」——绝不再假装跳转后 4 秒才悄悄弹回
   （这正是你看到「面板动了本体不动」的旧观感来源）。
3. **暂停→再播放累积漂移归零**：宿主改为**插件真值绝对锚定**——插件每秒把
   客户端内 `el.currentTime`（帧级真值）报上来，进度/歌词每拍直接锚到真值，
   暂停/恢复/微 seek 的误差**不可能累积**（构建内三轮暂停恢复实测偏差
   0.03%→0.06%→0.05%，无累积趋势）。
4. **桥合并进扩展体验**：静默自启 + 端口接管 + 自愈升级（见「二」），
   不再需要保持任何窗口。

## 四、自检清单（2 分钟）

1. 网易云播放一首带歌词的歌 → 新标签页 dock 音乐按钮 → 面板亮起、歌词滚动。
2. 页脚显示 `已连接 · 网易云音乐 · 插件 v1.2.0`。
3. 拖动面板进度条到 2:00 → **网易云本体进度条跟着跳**（内部 API 生效）。
4. 暂停 → 等 5 秒 → 继续：歌词/进度无跳变（真值锚定）。
5. Windows 音量弹窗（点任务栏音量图标）里如果连系统自带的媒体浮层都拖不动
   网易云的进度，那就坐实了网易云 SMTC 的 seek 是客户端级残废——这正是我们
   改走内部 API 的原因，与「初始」无关。

## 五、常见问题

- **页脚没有「插件 v…」**：插件没装好。确认 BetterNCM 已装、plugins 里有且仅有
  `初始歌词源-1.2.0`（删掉旧版），重启网易云。
- **拖动提示「未生效」**：说明插件没法在客户端里执行 seek（旧版客户端结构变化）。
  请反馈网易云客户端版本号；此时面板会诚实弹回，不会假跳。
- **桥起不来**：`启动SMTC桥.bat` 窗口里会写原因；v1.6.0 已能自动接管旧实例，
  一般只剩「端口被第三方程序占用」一种情况，改 bat 里 `-Port 20755` 即可
  （插件配置里也要改成同端口）。
