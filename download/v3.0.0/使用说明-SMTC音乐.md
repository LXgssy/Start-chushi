# 「初始」SMTC 音乐 · v3.0.0 双插件架构使用说明

> 本版是**架构重写版**：旧版「初始歌词源」一体化插件拆分为两个职责单一的插件，
> 根治多层真值互相打架导致的播放状态反转、进度爬行/冻死、组件版本误报等结构性问题。
> **样式与交互完全不变**——播放键位移、面板高度跳动、拖动无提示等历史修复全部保留。

## 一、为什么要拆成两个插件

旧版把「桥进程管理」和「网易云状态生产」塞在一个插件里，同时宿主/桥/插件三层都在
各自"修正"进度数据，层与层互相覆盖——这就是播放状态反着来、进度 0.5 倍爬行、
时间显示 0:00、插件明明最新却喊旧版的根源。

v3.0.0 每数据单主：

| 组件 | 职责（只有这一件事） |
|------|---------------------|
| **初始SMTC桥**（新插件A） | 桥进程生命周期：自动部署/拉起/杀旧/监督/开机自启，向桥上报自己的版本 |
| **初始网易云API**（新插件B） | 网易云真值唯一生产者：精确进度/播放态/逐字歌词/seek 执行 |
| 桥 v2.0.0（PS1） | 纯传输：不再修正任何数据 |
| 「初始」宿主 | 唯一仲裁：插件在场 → 插件真值独占；不在场 → SMTC 兜底 |

## 二、安装 / 迁移（三步）

1. **卸载旧版**：BetterNCM 插件管理里卸载「初始歌词源」（1.3.0–1.5.1 都算旧版）。
2. **安装两个新插件**：把本包内 `初始SMTC桥-2.0.0.plugin` 与
   `初始网易云API-2.0.0.plugin` 放入 BetterNCM 的 `plugins` 文件夹。
3. **重启网易云音乐**。桥会自动部署并静默拉起（零窗口），新标签页播放音乐即接入。

> 换过桥端口的话：两个新插件的「桥端口」配置必须一致（默认 20754，无需改动）。

## 三、手动兜底（仅当自动拉起被系统策略拦截）

部分机器的策略/杀软会拦截进程创建。若面板提示「桥未运行」：

- 打开本包 `手动启动桥（备用）` 文件夹，双击 `启动SMTC桥.bat`；
- 或重启电脑后再试（插件会在网易云启动时自动重试拉起）。

## 四、本版修复与保留清单

**根治（新架构）**

- 播放状态反转：「初始」显示与网易云实际状态不再概率性相反
- 进度 0.5x 爬行 / 倒退 / 冻死 0:00：三层修正互打已终结，真值只出一层
- 组件版本误报：版本各查各的活源（桥版本 / API 插件心跳 / 管理插件注册表），
  面板芯片文案与真实可行的操作一一对应，绝不再喊无效的「更新 .plugin」
- 旧插件与新插件并存冲突：桥按 role 仲裁，新插件心跳优先，不会互打

**保留（历史真机修复，防回归）**

- 播放/暂停按钮零位移（双 SVG 同圆心堆叠 + 交叉淡切）
- 面板高度迟滞（同曲丢词不塌高度，按钮不位移）
- 按钮乐观翻转（点击立即反馈）
- 拖动失败醒目芯片 + 诚实弹回（绝不假装已跳转）
- seek 三级阶梯 + 逐级实测校验（channel.seek → store dispatch → 元素直写）
- 逐字歌词（yrc）+ 翻译对齐 + 暂停恢复不漂移
- WSH 零弹窗（直启 powershell 优先 + On Error 静默 + 部署读回校验 + 失败退避）

## 五、面板提示对照表

| 面板芯片/页脚 | 含义 | 该做什么 |
|---------------|------|----------|
| 已连接 · API v2.0.0 · 管理 v2.0.0 | 全部正常 | 无 |
| 未装「初始网易云API」 | 缺真值插件（SMTC-only 模式） | 安装 初始网易云API-2.0.0.plugin |
| 双插件迁移 | 旧「初始歌词源」还在用 | 按第二节迁移三步走 |
| 桥未运行 | 桥进程不在 | 装 初始SMTC桥 插件自动管理，或双击 启动SMTC桥.bat |
| 旧桥进程未被自动替换 | 旧桥进程杀不死（策略拦截） | 双击 启动SMTC桥.bat / 重启电脑后重试 |
| 拖动未生效：播放器未响应 | 本次 seek 播放器没跟上 | 已诚实弹回真实进度，可重试 |
