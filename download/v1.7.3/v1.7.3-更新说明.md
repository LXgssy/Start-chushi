# 「初始 · Start-chushi」v1.7.3 更新说明

> 发布日期：2026-09-04　|　网页版：https://lxgssy.github.io/Start-chushi/　|　仓库：https://github.com/LXgssy/Start-chushi

本批为**壁纸视频修复批**，针对 v1.7.2 视频壁纸功能的两类实际使用问题。

---

## ① 修复「视频导入后壁纸没反应」（HEVC 编码黑屏）

**根因**：实测视频为 **HEVC（H.265）编码**的 4K 60fps MP4。Chrome/Edge 默认不带 HEVC 解码器（Edge 需系统安装「HEVC 视频扩展」），浏览器解不出画面 → `<video>` 永远不触发 canplay → 壁纸层恒为透明，且导入时不报任何错误，看起来就是「导入后没反应」。

**修复**：导入视频（本地上传与直链 URL）前先做**可解码性探测**——后台临时建一个视频元素实际试播：

- 试播成功 → 正常入库生效；
- 试播失败（编码不支持）→ 明确提示「当前浏览器不支持该视频编码（常见于 HEVC/H.265），请转码为 H.264 的 MP4 后再试」，文件不会入库，壁纸不受影响；
- 超时（大文件/慢网）→ 放行导入，不误拒。

> 附：本次已将用户的 4K HEVC 视频转码为 **H.264 1080p60 壁纸版**（43MB → 8MB，画质足够壁纸场景，浏览器通用可解码），随交付包一并送上。

## ② 修复「导入视频后壁纸不刷新」

**根因**：当已处于自定义壁纸模式时再导入新文件，`photoId` 与 `wallpaperUrl` 两个依赖都没变化，渲染端的壁纸加载逻辑不会重新执行——新文件已入库，壁纸却停在旧画面。该问题同样影响重复导入图片。

**修复**：新增设置字段 `wallpaperRev`（导入版本号），每次导入自增并强制渲染端重读壁纸源。custom 模式下反复换壁纸（本地文件或 URL）现在都会立即走黑幕过渡换装；设置面板里的自定义缩略图同步刷新。

## ③ 视频直链 URL 导入同样探测 + 强制刷新

- 粘贴视频直链回车 → 先探测远端视频可解码性，链路失效或编码不支持即拒绝并提示（探测期间显示「正在探测直链视频…」）；
- 重复导入同一 URL（如对端已更换内容）也会强制刷新，不再因 URL 未变而忽略。

## 升级说明

- **网页版**：刷新页面即自动换装（Service Worker 后台静默更新，无需手动操作）。
- **扩展版**：下载 `ChuShi-NewTab-v1.7.3.zip` 解压后，在 `edge://extensions` → 管理扩展 → 「初始」→ 重新加载（或先移除再「加载解压缩的扩展」选择新目录）。数据（磁贴 / 待办 / 便签 / 预设 / 自定义壁纸）全部本地保留，无迁移操作。
- **视频壁纸小贴士**：壁纸视频推荐 **H.264 编码 MP4**（Chrome/Edge 通用）；HEVC/H.265 需要系统额外装解码器，不建议直接用。已装 HEVC 扩展的 Edge 上 HEVC 视频可正常导入播放。
