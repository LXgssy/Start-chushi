# 「初始」SMTC 音乐 · v3.1.0 使用说明

> 本版按你的指令把 SMTC 彻底重写为**满血版**：不再依赖网易云自带的残疾 SMTC
> （position 不动、悬浮窗拖动被静默忽略），桥自带一个真实的系统媒体会话，
> 由网易云插件真值驱动。同时落地逐字歌词防累积漂移方案。
> 面板样式与交互完全不变，播放键零位移、高度迟滞、诚实弹回等历史修复全部保留。

## 一、v3.1.0 做了什么

| 新能力 | 位置 | 说明 |
|--------|------|------|
| **满血版自有 SMTC 会话** | 桥 v3.0.0 | 桥用 MediaPlayer + 官方手动控制模式自建一个真实媒体会话：时间线每秒墙钟推进、**Windows 悬浮窗/锁屏进度条真实可拖**、播放/暂停/上一首/下一首可用；网易云自带的残疾 SMTC 从此不承担任何角色 |
| **控制全回路** | 桥 + 插件B v2.2.0 | 系统媒体键/悬浮窗按钮 → 桥直控网易云会话，失败自动落到插件页内执行（锁定元素 play/pause 优先 + 页脚可见按钮兑底）；**悬浮窗拖动进度 → 插件页内 seek 阶梯**（网易云唯一接受的路径） |
| **控制门修复** | 桥 v3.0.0 | 桥抓不到网易云 SMTC 会话时（虚拟曲目场景），面板播放/暂停/拖动不再死路——自动转发插件页内执行；拖动命令的旧标题匹配门废除（真机「拖了没反应」的桥侧根因） |
| **seek 加固** | 插件B v2.2.0 | 直写元素后 1.6s 末级重写（防本体重置元素）；**身份捕获**——被直写且真实生效的元素立即锁定为主播放器，后续真值读取不再漂移 |
| **逐字歌词防漂移** | 渲染层 | 按你的思路落地：API 插件取全量 yrc 歌词 → 真值时间轴对齐（slew 微抖吸收 ≤0.35s，扫色不再肉眼抖动）→ **暂停时按词时间轴计算淡入淡出时长**（淡出收敛在本词边界内，恢复淡入）——冻结感与累积漂移感知归零 |

## 二、升级（三步）

1. **更新浏览器扩展**：用本包 `ChuShi-NewTab-v3.1.0.zip` 替换旧版（或按你原来的方式更新）。
2. **更新两个网易云插件**：BetterNCM 插件管理里卸载旧的「初始SMTC桥」「初始网易云API」，
   放入本包 `初始SMTC桥-2.1.0.plugin` + `初始网易云API-2.2.0.plugin`。
3. **完全重启网易云音乐**（桥会由插件自动升级：部署新版→杀旧进程→拉起，无需手动）。

> 从 v2.x 一体化「初始歌词源」升级：先卸载旧「初始歌词源」，再装两个新插件，重启网易云。
> 若升级芯片显示「旧桥进程未被自动替换」（系统策略拦截杀进程）：双击交付包内
> 「手动启动桥（备用）/启动SMTC桥.bat」或重启电脑。

## 三、装完自查（30 秒）

1. 播放一首有逐字歌词的歌；打开「初始」音乐面板看页脚：
   - `已连接 · NetEase Music · API v2.2.0 · 管理 v2.1.0` = 全部正常；
   - 只显示 `管理 v2.1.0` 没有 `API v2.2.0` = 插件B 未加载（确认已替换并重启网易云）。
2. **Windows 悬浮窗/锁屏**（音量键旁边的媒体浮层）：应出现网易云曲目卡片，
   进度条每秒前进、可以拖动；按播放/暂停键音乐应响应。
   > 悬浮窗里可能会同时出现网易云官方卡片与本桥卡片，用**本桥的卡片**（可拖动的那张）。
3. 面板内：进度条拖动后歌曲应跳转；暂停时逐字歌词淡出、恢复时淡入。

## 四、面板提示对照表

| 面板芯片/页脚 | 含义 | 该做什么 |
|---------------|------|----------|
| 已连接 · API v2.2.0 · 管理 v2.1.0 | 全部正常 | 无 |
| 组件待更新 | 插件版本低于 2.2.0 / 桥低于 3.0.0 | 按更新说明替换对应 .plugin，重启网易云 |
| 未装「初始网易云API」 | 缺真值插件 | 安装 初始网易云API-2.2.0.plugin 并重启网易云 |
| 双插件迁移 | 旧「初始歌词源」还在用 | 卸旧装双新插件，重启网易云 |
| 桥未运行 | 桥进程不在 | 装 初始SMTC桥 插件自动管理，或双击 启动SMTC桥.bat |
| 旧桥进程未被自动替换 | 旧桥进程杀不死（策略拦截） | 双击 启动SMTC桥.bat / 重启电脑后重试 |
| 拖动未生效：播放器未响应 | 本次 seek 播放器没跟上 | 已诚实弹回真实进度，可重试 |
