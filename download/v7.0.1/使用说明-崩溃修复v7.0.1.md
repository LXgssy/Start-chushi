# ChuShi SMTC Manager v7.0.1 — 崩溃紧急修复

## 这一次发生了什么

v7.0.0 的原生 SMTC 模块在「把播放进度推给系统媒体卡片」时，对 Windows 的
`SystemMediaTransportControlsTimelineProperties`（时间线属性）错误地调用了 WinRT
激活接口。**它是一个值结构体（struct），根本没有激活工厂**，在网易云进程内这一调用
直接崩溃——这就是你看到的：

```
BetterNCM CrashReport:
  combase.dll (RoActivateInstance)
  smtc_native.dll + 0x235F
```

由于系统媒体卡片需要持续接收进度才会显示完整内容，所以表现为：**装上后播歌必崩**。
本次崩溃与网易云自带的 SMTC 开关无关，开或关都会崩。

## v7.0.1 修了什么

1. **崩溃根因清除**：时间线属性改为按 Windows ABI 直接栈上构造结构体传参
   （`ISystemMediaTransportControls2::UpdateTimelineProperties`），彻底删除对该
   结构体的激活调用；反汇编级验证 DLL 内已无任何 `RoActivateInstance` 引用。
2. **全部 WinRT 接口逐项复核**：9 个接口 GUID、vtable 槽位序、事件特化 IID 全部
   对照 windows-rs 官方投影源码与 MinGW-w64 官方 IDL 逐项验证（interop
   `GetForWindow`、SMTC/SMTC2、DisplayUpdater、MusicDisplayProperties 等）。
3. **Host 自愈**：本插件在网易云的多个进程里只选举一个「Host」承载系统会话；
   v7.0.1 起，Host 若注册失败会自动让位给其它进程重试，不再死守。
4. **HTTP 枢纽并发化**：本机 26901 端口枢纽改为每连接独立线程，慢请求不再拖累
   每秒心跳，页面数据更稳。
5. **新增文件日志**：出问题时直接把这个文件发给 AI 即可定位（见下）。

## 安装步骤（重要：先删旧再装新）

1. 完全退出网易云音乐（托盘右键退出）。
2. 打开 `C:\betterncm\`，进 `plugins` 文件夹，**删掉旧的
   `ChuShi-SMTC-Manager-7.0.0.plugin`**（其余两个插件
   `ChuShi-Music-Bridge-7.0.0.plugin`、`ChuShi-Lyric-Source-7.0.0.plugin` 不用动）。
3. 把 `ChuShi-SMTC-Manager-7.0.1.plugin` 放进 `plugins` 文件夹。
4. 重新打开网易云音乐。插件列表里 SMTC Manager 应显示 7.0.1。
5. 保持网易云自带的 SMTC/「系统媒体」相关开关**关闭**——本插件自带满血系统会话，
   不需要也不建议再开网易云自己的。

## 验证清单

- [ ] 播放一首歌，**网易云不再崩溃**
- [ ] Windows 音量悬浮窗 / Win+K 媒体浮层出现「初始」卡片（歌名/歌手/封面）
- [ ] 卡片进度条可拖动，拖动后网易云播放位置跟随
- [ ] 键盘媒体键（播放/暂停/上一首/下一首）生效
- [ ] 「初始」新标签页音乐面板显示正在播放的歌曲，进度条与时间随播放走

## 如果还有问题：把日志发给 AI

v7.0.1 会在插件目录写日志：

```
C:\betterncm\plugins_runtime\ChuShi-SMTC-Manager\native-log.txt
```

正常日志长这样：

```
[boot] ChuShi SMTC Manager native v7.0.1 loaded (ptype=0x1)
[boot] elected as host, starting smtc + http threads
[smtc] RoInitialize ok (MTA)
[smtc] GetForWindow OK — system media session registered
[http] hub listening on 127.0.0.1:26901
[upd] timeline applied first time pos=...
```

把这个文件直接发给 AI，一切失败（会话注册、端口、事件）都会记录在案，
不再需要猜测。技术说明：每次打开网易云日志会追加，超过 1.5MB 自动重建。
