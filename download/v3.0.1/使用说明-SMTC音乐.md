# 「初始」SMTC 音乐 · v3.0.1 使用说明

> 本版针对真机反馈的四个症状做定点根治：**逐字歌词不动/坏、播放状态不同步、
> 进度条不动、数字时间不变**。架构不变（v3.0.0 双插件），样式与交互完全不变，
> 播放键零位移、面板高度迟滞、拖动失败诚实弹回等历史修复全部保留。

## 一、v3.0.1 修了什么

四个症状的共同根源是「网易云真值断供/失真」——面板拿不到在动的真值时，
SMTC 兜底路径的进度本来就是冻结的（这正是当初自写网易云 API 的原因）。
本版三处根治：

| 根治点 | 位置 | 解决什么 |
|--------|------|----------|
| **虚拟曲目兜底** | 宿主 v3.0.1 | 桥抓不到网易云 SMTC 会话时（真机常见：新版网易云 SMTC 注册变化/会话被抢占），插件B 的真值不再被弃用——旧版此时回退 SMTC-only，进度/时间/逐字歌词全冻结 |
| **播放态物理自愈** | 网易云API 插件 v2.1.0 | 播放态事件丢失/失真时以物理事实为准：**进度在推进 = 在播放**——面板不再显示暂停实际在响，进度条/时间/逐字歌词不再因「锚点冻结」全部停摆 |
| **store 次级真值** | 网易云API 插件 v2.1.0 | 原生进度事件死 + 元素不可信时，用网易云自家进度条同源的 store 数据兜底，进度不再冻死在 0 或旧值 |

## 二、升级（两步）

1. **更新浏览器扩展**：用本包 `ChuShi-NewTab-v3.0.1.zip` 替换旧版
   （扩展管理页 → 移除旧「初始」→ 加载本 zip 解压后的文件夹），或按你原来的安装方式更新。
2. **更新网易云插件**：BetterNCM 插件管理里卸载旧的「初始网易云API」（2.0.0），
   放入本包 `初始网易云API-2.1.0.plugin`；「初始SMTC桥-2.0.0.plugin」**不用动**。
   然后重启网易云音乐。

> 已装 v3.0.0 双插件的用户：无需卸装「初始SMTC桥」，只换 API 插件即可。
> 从更早版本（v2.x 一体化「初始歌词源」）升级：先卸载旧「初始歌词源」，
> 再装两个新插件，重启网易云（详见 v3.0.0 迁移三步走）。

## 三、装完自查（30 秒）

1. 播放一首有逐字歌词的歌（如热门曲目）；
2. 打开「初始」音乐面板，看页脚：
   - `已连接 · NetEase Music · API v2.1.0 · 管理 v2.0.0` = 全部正常；
   - 只显示 `管理 v2.0.0` 没有 `API v2.1.0` = 插件B 未加载（检查是否已替换并重启网易云）；
   - 亮起升级芯片 = 按芯片文案操作（文案与真实可行操作一一对应）。
3. 进度条应每秒平滑前进、时间数字跳动、逐字歌词按字扫色。

## 四、面板提示对照表

| 面板芯片/页脚 | 含义 | 该做什么 |
|---------------|------|----------|
| 已连接 · API v2.1.0 · 管理 v2.0.0 | 全部正常 | 无 |
| 未装「初始网易云API」 | 缺真值插件 | 安装 初始网易云API-2.1.0.plugin 并重启网易云 |
| 双插件迁移 | 旧「初始歌词源」还在用 | 卸旧装双新插件，重启网易云 |
| 桥未运行 | 桥进程不在 | 装 初始SMTC桥 插件自动管理，或双击 启动SMTC桥.bat |
| 旧桥进程未被自动替换 | 旧桥进程杀不死（策略拦截） | 双击 启动SMTC桥.bat / 重启电脑后重试 |
| 拖动未生效：播放器未响应 | 本次 seek 播放器没跟上 | 已诚实弹回真实进度，可重试 |
