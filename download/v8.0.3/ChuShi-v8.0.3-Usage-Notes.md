# 「初始」v8.0.3 控制末端加固版使用说明

## v8.0.3 修了什么（对应你本次反馈的四个问题）

| 问题 | 根因 | 修复 |
|---|---|---|
| 播放/暂停、上一首/下一首点击后没反应 | **最大嫌疑：音乐桥插件仍是旧版**——v8.0.2 的控制修复全在插件层（按钮三步验证+逐级降级），而歌词修复在预设部件层（重导入 cshz 即生效），所以会出现「歌词好了、按键还坏」的组合。若已是 8.0.2 桥：则是网易云 3.x 上 InfLink 派发、redux 直发、audio 元素、按钮选择器四级全部未命中 | ①桥 8.0.3 末端加固：按钮候选扩宽（aria-label/title 中文关键词「播放/暂停/下一首/上一首」+ class 模糊匹配，NCM 3.x 改版 DOM 兼容；「播放列表」类按钮误中保护）；②点击改完整指针事件序列（pointerdown→mousedown→pointerup→mouseup→click）；③toggle 元素路径 +700ms 复验（元素自身状态即算生效，防双翻转）。**部件侧新增控制诚实反馈**：点击后 3.2 秒内真值未翻转，面板亮红色芯片并按版本归因——「音乐桥插件 vX 控制能力不足 → 请更新插件」或「控制已下发但网易云未响应 → 请完全重启网易云」，不再静默无反应 |
| 播放/暂停键悬停变黑 + 图标位移 | 部件 CSS：`.cs-b:hover` 的半透明暗底/深色前景/scale 与主键的 accent 白图标三重冲突（同特异性按源码顺序胜出——悬停时暗底盖掉 accent、白图标变色、整体微放大读作位移） | 主键悬停律：恒保 accent 底 + 白图标，仅亮度提升 12%，零位移变换（台架实测 hover 背景色/前景色/transform 三断言） |
| 中文歌词没有逐字效果 | 歌词源 klyric（网易旧逐字格式，中文歌主力逐字源）转换器输出的是 LRC 式逐词时间戳，逐字渲染器不认 → 中文歌整首退化成行级歌词；另外 eapi 逐字请求未携带登录凭据（yrc 只对登录会话下发） | ①klyric 转换改发真 yrc 时间轴（`[行起,行长](词起,词长,0)词…`，与渲染器解析器往返验证通过）；②eapi 优先带登录凭据（credentials include，官方 web 播放器同款）；③新增同源 web v1 备路（music.163.com 自带 cookie，免加密免 CORS） |
| 网页端没有播放进度调节 | seek 也走控制链路（同样受上述问题影响）；且进度条滑块暗示可拖动 | 按你的要求：**进度条改为纯只读**——滑块删除、拖拽交互删除，只留不可调节的填充进度条（时间显示保留） |

## 更新步骤（照做即可）

1. 关闭网易云，进 `C:\betterncm\plugins`：**删掉旧 ChuShi-Music-Bridge-8.0.2.plugin**（以及
   8.0.1/8.0.0），放入 `ChuShi-Music-Bridge-8.0.3.plugin`；删掉旧
   `ChuShi-Lyric-Source-7.0.0.plugin`，放入 `ChuShi-Lyric-Source-7.1.0.plugin`
   （中文逐字修复在歌词源插件里，**必须一起换**）。
2. 完全退出并重启网易云（托盘右键退出，不是关窗口）。
3. 「初始」页更新到 v8.0.3（线上 Pages 已同步；扩展用户覆盖安装）。
4. **「初始」页重新导入 `ChuShi-Music-Preset-8.0.3.cshz`**（悬停修复、只读进度条、
   控制未生效提示芯片都在部件里，必须重导入）。
5. InfLink-rs 保持 3.2.11 启用。

## 验收点

- 点播放/暂停/上一首/下一首，网易云真实响应；如果点了仍没反应，面板会在
  3 秒左右**亮红色芯片告诉你原因**（插件过旧 → 换插件；网易云未响应 → 完全
  重启网易云），把芯片文案发我们即可精确定位。
- 鼠标悬停播放/暂停键：按钮保持主题色底 + 白色图标，只有轻微提亮，不变黑不位移。
- 中文歌歌词逐字扫色（卡拉OK效果）随演唱推进；双语歌已唱行灰色、当前行高亮 + 翻译。
- 进度条为只读样式（无圆形滑块、拖动无反应），时间数字照常走。
- 诊断口仍在：网易云开发者控制台 `window.__chushiMusicBridge.debug().cmdTrace`
  可看每条控制命令的执行轨迹（InfLink→redux→element→button 走到哪一级）。
