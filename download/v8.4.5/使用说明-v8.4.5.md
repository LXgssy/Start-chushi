# 「初始」v8.4.5 更新说明——本地直载壳（加载即缓存 · 新标签页秒开 · 地址栏收敛）

## 这版解决了什么（对应你的三条指令）

| 你的指令 | v8.4.5 落地 |
|---|---|
| 「加载完成后直接缓存在本地」 | 云端新版由后台静默下载，文件集全量缓存进浏览器本地数据库（IndexedDB），原子提交、半途失败零感知 |
| 「新开标签页时直接就加载最新的版本即可」 | 新标签页启动路径**零网络**：只读本地做版本路由（内嵌版 vs 缓存快照取较新者），断网也完整可用。探针实测 boot 257ms（v8.4.4 是 10 秒握手量级） |

## 架构反转说明（v8.4.4 → v8.4.5）

v8.4.4 学习青柠起始页的云端壳：新标签页 iframe 载 GitHub Pages 云端版 + 10 秒握手、超时才回退本地。实机暴露三个问题：每次开新标签页都等云端、GitHub Pages 境内不稳时白等、地址栏挂云端链路。

v8.4.5 反转为**本地直载**：

1. **内嵌完整版就是最新版**——新标签页直接加载扩展内嵌的完整「初始」，零网络；
2. **云端静默更新**——后台每 6 小时（+启动时）比对云端 `version.json`，发现**严格更新**的版本才下载缓存（永不降级，旧云端版本不可能覆盖你的新版）；
3. **快照直载**——缓存完成后，下一个新标签页起直载缓存快照（`/cs-snap/` 虚拟目录，子路径 Service Worker 从本地数据库合成响应，离线可用）。

云端更新机制学习自你发的青柠起始页 1.4.0 crx（壳 + 云端内容 + 版本逃生门），并按你的设计做了增强：壳桥（扩展页监听 iframe postMessage、校验 origin 白名单、代写 chrome.storage.local）保留在包内，云端模式兼容如初；本地模式下页面与扩展同源，自带 chrome API，**面板与浮窗开关经 chrome.storage 原生同步**（比桥更快更稳）。

## 关于地址栏，一句诚实话

Chrome 强制新标签页扩展显示自身页面地址（`chrome-extension://<32位ID>/文件名`），青柠、WeTab 等所有同类扩展都一样，**完全空白是 Chrome 不允许的**。本版已做到极限：无参数、无跳转、无云端网址，只剩扩展 ID + 文件名；按 F5 直接刷新应用本体（自足运行，绝不会 404）。

## 云端更新源怎么用（可选，机制已就绪）

包内附 `ChuShi-CloudSnapshot-v8.4.5.zip`（69 个文件的云端快照载荷 + version.json）。将来想让某台设备走云端更新：把载荷解压部署到任意 https 静态托管（GitHub Pages / 自己的服务器 / 对象存储），扩展后台会自动发现并缓存。**本版未部署任何公开源、未推送公开仓库**——是否部署、部署到哪，完全由你决定。

## 安装 / 升级

1. 下载并解压 `ChuShi-NewTab-v8.4.5.zip`；
2. 删除旧版本目录（设置都存在浏览器里不会丢）；
3. Chrome → `chrome://extensions` → 开发者模式 → 「加载已解压的扩展程序」→ 选新目录；
4. 音乐面板用户：`初始SMTC音乐预设.cshz` 与 v8.4.4 相同（本版未改预设），已装无需重装。
